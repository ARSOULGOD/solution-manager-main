# Release the two images (launcher and agent): licences, notices, source offer

| | |
|---|---|
| **Applies to** | `sm-launcher` (`runtime/`, built by `runtime/scripts/build-image.sh`) and `sm-agent` (`go-agent/Dockerfile`); owner rulings `OR-127` (L1 to L4), `OR-130`, `OR-134`, `OR-135`; `REQ-014` / `I8` |
| **Severity** | routine, **but a release is not complete until every item below is true** |
| **Est. duration** | about an hour, plus the builds |
| **Reversible?** | An image that has been **distributed** cannot be recalled; the offer in step 5 then binds you for its stated term. Nothing in this runbook distributes anything. |
| **Status** | **`UNTESTED` draft.** The offer wording below is **not legal advice and not approved**: the owner (or counsel) must confirm it and fill the contact before the first image leaves your organisation. |

## When to use

Before an image is given to anyone outside the team that built it (a customer, a registry others can pull from, an installer).

## Preconditions

- The tree is the reviewed release commit; `git status` is clean.
- Docker with buildx; the toolchain the builds need (`mvn`, JDK 17+ for the build; Go for the agent). Neither build is run by this runbook's text beyond the commands in step 1.

## Steps

### 1. Build, with no `-Dprotoc*` flag

```bash
./contracts/run-checks.sh --strict                                    # includes the proto append-only step (18) and the licence-gate / protoc-pin steps (16, 17)
runtime/scripts/build-image.sh <tag> --check                          # the launcher image; --check builds twice and fails unless the manifest digests match
docker build -t sm-agent:<tag> go-agent                               # the agent image (the Dockerfile pins both bases by digest)
```

`build-image.sh` runs `mvn -o -q -DskipTests -DskipITs verify -pl launcher -am`: **`verify`, not `package`**, because the `I8` licence gate is bound to `verify`. Never set `SM_SKIP_MVN=1` for a release (it skips the licence gate).

**The build command carries no `-Dprotoc*` flag, and no `.mvn/*.config` sets one.** `-DprotocExecutable`, `-DprotocPluginExecutable` and `-DprotocPlugin{Tool,Toolchain}` swap the audited protoc binaries for others; `backend/scripts/check-protoc-executables.py` refuses them in poms and `.mvn/*.config`, but **not in a shell command**, so this is a rule of the person running the build. If a release build needs one, stop: it is an owner question (`OR-130` L-b/L-c).

### 2. The licence gates

Run, and keep the output with the release record:

```bash
python3 backend/scripts/check-licences.py                 # I8: the Java dependency gate, its allow-list and exceptions
backend/scripts/test-check-licences.sh                    # the gate's own planted-violation proofs
backend/scripts/test-licence-gate-present.sh              # the gate is still wired into the build
python3 backend/scripts/check-protoc-executables.py
(cd go-agent && scripts/check-licences.sh)                # the agent: no compiled-in module outside THIRD-PARTY-LICENCES.md
```

(These are the scripts as they exist in the tree; `backend/pom.xml`'s licence plugin is the gate that `verify` runs. A coordinate or version that changed since the last release returns to the owner (`OR-135`: "a changed version returns to the owner").)

### 3. The NOTICE obligations (`OR-127` L3)

Each image carries its notices; check them **inside the built image**, not in the tree:

| Image | Files in the image | Source in the tree |
|---|---|---|
| launcher | `/usr/share/doc/sm/NOTICE`, `/usr/share/doc/sm/THIRD-PARTY-NOTICES.md` (both 0444, the directory 0755) | `runtime/launcher/NOTICE`; `backend/THIRD-PARTY-NOTICES.md` (copied by `build-image.sh`) |
| agent | `/usr/share/doc/sm-agent/NOTICE`, `/usr/share/doc/sm-agent/THIRD-PARTY-LICENCES.md` | `go-agent/NOTICE` (generated by `go-agent/scripts/gen-notice.sh`; the Apache-2.0 section 4(d) NOTICE files of the compiled-in modules); `go-agent/THIRD-PARTY-LICENCES.md` |

The launcher's notices must contain, and you must confirm in the built image:

- **The BoringSSL notices** for the TLS library embedded in `io.grpc:grpc-netty-shaded:1.68.1` (ISC and OpenSSL-style licence text, reproduced verbatim from the jar's `META-INF/license/LICENSE.boringssl.txt` in `backend/THIRD-PARTY-NOTICES.md`).
- **The OpenSSL License text for the AIX/NetBSD code in the same jar** (`META-INF/license/LICENSE.aix-netbsd.txt`), reproduced there too (clause 2: binary redistributions reproduce the copyright notice, conditions and disclaimer).
- **The OpenSSL clause 3 advertising acknowledgment**, which `runtime/launcher/NOTICE` carries and which must be present, and displayed wherever advertising materials mention features or use of this software:

  > This product includes software developed by the OpenSSL Project for use in the OpenSSL Toolkit (http://www.openssl.org/)

  (T1.2 review note (b). The OpenSSL toolkit itself is not part of the product; the acknowledgment is the licence's condition for the NetBSD/AIX code.) A different version of `grpc-netty-shaded` fails the build until its NOTICE and these texts are re-read and re-approved.

```bash
docker run --rm --entrypoint cat sm-launcher:<tag> /usr/share/doc/sm/NOTICE | grep -c 'OpenSSL Project for use in the OpenSSL Toolkit'   # expect 1 or more
docker create --name sm-agent-notice sm-agent:<tag> && docker cp sm-agent-notice:/usr/share/doc/sm-agent/NOTICE ./NOTICE.check; docker rm sm-agent-notice   # a distroless image has no shell or cat to run; read ./NOTICE.check
```

### 4. What the images are made of (`OR-127` L4)

- Launcher base: `eclipse-temurin:21-jre-jammy`, pinned by digest in `runtime/launcher/Dockerfile`: the JRE is **GPL-2.0 with Classpath Exception**; the OS layer is Ubuntu 22.04 and carries Ubuntu package licences.
- Agent base: `gcr.io/distroless/static-debian13:nonroot`, pinned by digest in `go-agent/Dockerfile` (the builder `golang:1.26.4` is not shipped): Debian 13 package licences.
- **Not verified:** the per-package licence list of either OS layer at the pinned digests (the plan's section 9 marks it unverified). Before release, list the packages and their `copyright` files from the built images and attach them to the release record. A GPL or LGPL package you did not expect there changes step 5.

### 5. The corresponding-source offer (`OR-127` L4)

Redistributing an image that contains GPL-licensed components requires that the corresponding source be available to whoever receives it. GPL v2 section 3(b) (read from the licence text on 2026-10-12): *"Accompany it with a written offer, valid for at least three years, to give any third party, for a charge no more than your cost of physically performing source distribution, a complete machine-readable copy of the corresponding source code"*. The offer must **accompany the image**: a pulled image carries its NOTICE file, not your release notes, so once the owner has approved the text, **put it into both NOTICE files** (`runtime/launcher/NOTICE`; the agent's through `go-agent/scripts/gen-notice.sh`) and also publish it with the release notes and the registry entry:

> **Corresponding source.** The `sm-launcher` and `sm-agent` images contain software licensed under the GNU General Public License version 2 (with the Classpath Exception, for the Eclipse Temurin Java runtime) and under the licences of the Ubuntu 22.04 and Debian 13 distribution packages they are built from. For at least three years from the date you received the image, we will give any third party, for a charge no more than the cost of physically performing source distribution, a complete machine-readable copy of the corresponding source of those components, on written request to **`<source-offer contact, to be set by the owner>`**. The upstream sources are public: Eclipse Temurin / OpenJDK 21 updates (`https://github.com/adoptium/jdk21u`, an unmodified mirror of OpenJDK, read 2026-10-12), and the Ubuntu and Debian source package archives (`https://archive.ubuntu.com/ubuntu/pool/`, `https://deb.debian.org/debian/pool/`; both read as archive pools on 2026-10-12, source packages within them **not** confirmed). Solution Manager's own code is not part of this offer.

Items that are the owner's: the contact; the term (three years is the licence's minimum); whether to hold the source yourself (a mirror of what the pinned digests used) so the offer can be honoured if upstream moves. **Both NOTICE files state that the offer is owed pending the owner's approval, and name no repository path** (`runtime/launcher/NOTICE` is changed with this runbook; the agent's `go-agent/NOTICE` and `scripts/gen-notice.sh` are agent-PR paths, changed by a patch the integrator applies first). Until the approved text is in both files, no image is to be distributed.

### 6. Record

Add to the release record: the two image digests; the output of steps 1 and 2; the in-image NOTICE checks of step 3; the in-image `keytool` check (see [`enable-agent-gateway.md`](enable-agent-gateway.md#the-lease-nonce-hmac-key-required-before-the-first-start), owed before that runbook is merged); the package licence lists of step 4; the offer text as shipped and its contact.

## Verification

- `build-image.sh <tag> --check` reported matching digests; the licence scripts exited 0.
- The OpenSSL acknowledgment is in the launcher image's `NOTICE` (grep above).
- The approved offer text is in both NOTICE files (read inside the built images) and in the release notes for **both** images.

## Rollback

Do not publish. A published image is replaced by a newer tag; the offer made with the old one still stands for its term.

## Escalation

The owner (licences are `OR-127`'s, and any change of an approved coordinate or image is theirs) and counsel for the wording of the offer.
