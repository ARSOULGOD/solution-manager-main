# Checklists

Development-time process gates. For **operators**, see `../runbooks/`.

| Checklist | Use when |
|---|---|
| [`spec-review.md`](spec-review.md) | A design or sub-spec is written and about to be treated as done |
| [`plan-review.md`](plan-review.md) | An implementation plan is written, before execution starts |
| [`definition-of-done.md`](definition-of-done.md) | A task or PR is about to be marked complete |
| [`new-module.md`](new-module.md) | Standing up a module at the repo root |
| [`external-review-prompt.md`](external-review-prompt.md) | Getting the design reviewed by an independent model or person |
| [`a11y-checklist.md`](a11y-checklist.md) | A PR touches a screen or shared component; before a release |
| [`a11y-manual-keyboard-script.md`](a11y-manual-keyboard-script.md) | Per release — the manual keyboard walkthrough `a11y-checklist.md` points at |

A checklist item earns its place only if it has caught a real problem, or prevents one with a known cost. Delete
items that never fire — a checklist nobody completes honestly is worse than none.
