# Dependency licence exceptions (REQ-014 / invariant I8, plan 010 T0.4b).
#
# Every line below is ONE owner approval of ONE exact coordinate AND version. There is no pattern, no wildcard
# and no version range. A different version of the same artifact is a different approval: licence-third-party.ftl
# aborts the build when a group:artifact listed here resolves to a version that is not listed, and
# scripts/check-licences.py does the same for build plugins.
#
# FORMAT (license-maven-plugin overrideUrl, java.util.Properties): groupId--artifactId--version=Name. The Name
# REPLACES the licences the artifact's POM declares, so an artifact that declares several licences carries the
# owner's recorded election and no longer fails the fail-closed rule (Q-L2 a-prime: where the artifact's own text
# states a choice, the allowed option is elected and recorded; with no stated connective, it fails closed).
# The Name also fixes the SCOPE of the approval. backend/pom.xml whitelists, per execution:
#   shipped execution (compile, runtime, provided, system): the six allow-list names, "Owner-approved (shipped)"
#                                                           and "Solace first-party".
#   test execution (test):                                  those, plus "Owner-approved (test-only)".
#   "Owner-approved (build-tool-only)" is whitelisted nowhere: a build-tool coordinate that reaches a project
#   dependency tree fails both executions. Build plugins are checked by scripts/check-licences.py.
# Do not write the pipe character, and do not wrap a line: it is a properties file.
#
# AUTHORITY. Rulings are the project owner's, who decides on behalf of the architect group
# (docs/tasks/licence-audit-2026-09.md owner decision table rows 1-43; plan 010 T0.1 Step 7, batch 5; the
# registered ids are in docs/design/DECISIONS.md):
#   OR-66 = owner ruling 2026-09-30: Q-L1 (a) + Q-L2 (a-prime) "elect a stated choice", and "Approve A and B"
#   OR-67 = owner ruling 2026-09-30 and 2026-10-05, batch 5 closed: "Approve all of C and E", the two waivers,
#           and row 41: container images are tools, approved by EXACT TAG, test-only.
#   OR-68 = owner ruling 2026-10-05: out of REQ-014 scope are the Maven installation, the JDK, and the never-run
#           site and deploy plugins (their POMs are absent from ~/.m2).
#   OR-83 = owner ruling 2026-10-05: org.eclipse.sisu:org.eclipse.sisu.plexus:0.9.0.M3 (EPL-2.0) approved
#           build-tool-only (audit row 18(b)), the sibling of row 18.
#   OR-84 = owner ruling 2026-10-05: a stated-choice election is an EXPLICIT reviewed line, one per artifact and
#           version, citing OR-66. The gate does not detect an "OR" connective, so a new dual-licensed library
#           fails the build until its election line is added.
#   OR-127 = owner ruling 2026-10-08 (plan 015 T0.2): L1 javax.annotation-api not taken; L2 bcpkix/bcutil 1.86 approved;
#           L3 grpc-netty-shaded 1.68.1 approved including its embedded BoringSSL (the line below pins that exact version);
#           L4 the two shipped container images.
#   OR-130 = owner ruling 2026-10-08 (L-a, L-b, L-c): animal-sniffer-annotations 1.24 shipped; four build-tool coordinates; dev tools.
#   OR-134 = owner ruling 2026-10-09 (L-d): HdrHistogram 2.2.2 under BSD-2-Clause and LatencyUtils 2.0.3 under CC0 1.0, shipped.
#   Row 41 (container images) is not a Maven coordinate and is not gated by Maven. The approved images are
#   busybox:1.36, postgres:14 and testcontainers/ryuk:0.12.0. The ryuk tag was READ from the pinned jar
#   (testcontainers-1.21.4.jar, org/testcontainers/utility/RyukContainer.class), not recalled: a Testcontainers
#   bump that changes it needs a new owner line.
#
# RECORDING AN ELECTION (OR-66, Q-L2 a-prime; explicit lines per OR-84). Where an artifact's own licence text STATES a choice (an exact
# SPDX "OR", or "at your option"), the allowed option is elected by one line below. The comment above that line
# must name the file the connective was read from and quote it verbatim. No new owner ruling is needed for a
# stated choice: OR-66 already is that ruling. The build never reads the licence text, so the line is the record
# and the person adding it is the reader (OR-84: the election is an explicit reviewed line, never inferred by the
# gate). Where the text states NO connective, that is not an election: it needs
# an owner ruling, or the dependency is replaced.
#
# OWNER WAIVERS. An artifact that states NO licence is accepted only by an explicit owner waiver, recorded under
# the approval name "Owner waiver (build-tool-only, no licence stated)". It is not a licence name: no Maven
# execution whitelists it, and scripts/check-licences.py accepts it only while the artifact's POM chain still
# declares no licence, and names every waiver when it passes. The two waivers are rows 19 and 20 (OR-67).
